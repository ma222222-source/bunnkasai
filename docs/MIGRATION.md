# 将来の技術移行の比較（R8 文化祭のあと検討する）

> 2026-09-29 Claude Code 作成。**R8（2026-10-23・24）は今の構成のまま行く**のが結論。移行はしない。
> ここは「来年以降に作り直すなら」の判断材料。

## いまの構成の評価

| 観点 | いま（index.html 1ファイル＋GAS＋スプレッドシート） |
|---|---|
| 費用 | 0円（GitHub Pages・GAS・スプレッドシート） |
| 運用のしやすさ | 先生・係員がシートを直接見て直せる。これが最大の強み |
| 性能 | 画面は速い（SW でオフライン可）。**GAS の応答が1〜5秒、ときに10秒超・404** が弱点。60秒キャッシュ＋控え返しで耐えている |
| 同時アクセス | GAS は同時実行30本まで。来場者は読み取りだけ・キャッシュで吸収している |
| 保守 | `index.html` が約1万行・約60万字。1ファイルなので差分は追いやすいが、探すのに時間がかかる |
| テスト | v138 で `tests/`（静的＋Playwright、GAS 模擬）と GitHub Actions を整えた |

## 選択肢（松・竹・梅）

| | 案 | 得るもの | 失うもの・手間 | 費用 |
|---|---|---|---|---|
| 梅 | **今のまま**＋ `index.html` の中を節ごとに整理（見出しコメントで区切る） | 何も壊さない | 大きなファイルのまま | 0円 |
| 竹 | **開発時だけ分割、公開時に1ファイルへまとめる**（`src/*.js` `src/*.css` → 小さな Node スクリプトで `index.html` を組み立てる。外部ライブラリなし） | ファイルが小さくなり探しやすい。公開物は今と同じ1ファイルなので、配信・SW・URL は変わらない | 組み立ての手順が1つ増える。組み立て忘れで古い画面が出る危険（CI で組み立て結果と一致するか確かめて防ぐ） | 0円 |
| 松 | **Vite＋TypeScript** で作り直し、データは GAS のまま | 型で間違いを減らせる。部品ごとに分けられる | 全面書き換え。ビルド工程と npm の依存が入る（RULES.md §3 の方針を変える必要）。生徒が引き継げるかが課題 | 0円 |
| ― | Next.js・Firebase・Supabase | リアルタイム同期（Firestore など）で GAS の遅さが消える | シートで直す運用が消える。無料枠の上限・アカウント管理・鍵の管理が増える。文化祭2日のためには重い | 無料枠内なら0円だが、上限超えで課金の可能性 |

## おすすめ

1. **R8 は梅**（今のまま）。本番1週間前（10/16〜）からは不具合修正と実機確認だけ
2. 文化祭のあと、来年も使うなら **竹**。公開物が1ファイルのままなので、今の配信・QR・スタンプの互換性を保てる。`tests/` がそのまま使える
3. GAS の遅さが来年も問題なら、読み取りだけを「GAS が1分ごとに JSON を GitHub Pages か Cloudflare に書き出す」形にする案を検討（来場者の読み取りが GAS を通らなくなる）。書き込み（係員の更新）は GAS のまま

松・Next.js 等は、運用する人（生徒・先生）がシートで直せなくなるので、R8 の運用を振り返ってから判断する。
